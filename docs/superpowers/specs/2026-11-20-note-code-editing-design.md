# 메모 코드 작성 개선 — 설계 (짧은 버전)

## 의도
지식 메모에 소스 코드·SQL을 자주 적는다. 폰과 PC 둘 다 많이 쓴다. 핵심은 **코드를 편하게 적고, 나중에 깔끔하게 읽는 것**이다.
노션식 블록 에디터(입력 중 서식, `/` 메뉴)는 원하는 것이 아니다.

## 목표 / 비목표
- 목표: Enter 자동 들여쓰기, 들여쓰기·내어쓰기(폰은 도구줄, PC는 Tab/Shift+Tab), 코드블록 삽입, 읽을 때 코드블록 색 강조
- 비목표: 일반 글 서식(굵게·목록·제목), 입력 중 색 강조, **미리보기 토글(사용자가 넣지 말라고 함)**
- 안티골: 폰 한글 입력이 지금보다 불안정해지는 것, 기존 메모 표시가 깨지는 것

## 접근 (검토한 것)
- **A. 기존 Textarea 강화 + 마크다운 코드블록 — 선택.** 저장 형식은 지금처럼 텍스트라 기존 메모와 그대로 호환되고, 폰 키보드·시트 처리도 유지된다.
- B. CodeMirror로 교체 — 입력 중 색 강조와 괄호 매칭이 되지만 번들이 150KB 이상 늘고, 모바일 한글 IME 문제가 있고, 키보드 높이 처리를 다시 해야 한다.
- C. TipTap 같은 블록 에디터 — 저장 형식(HTML/JSON)이 바뀌어 일이 크고, 목적에 덜 맞는다.

## 설계
**입력 칸 (`KnowledgeNoteFormDialog` 내용 Textarea)**
- 줄바꿈 처리
  - Enter로 줄바꿈하면 윗줄의 앞 공백을 그대로 이어 붙인다.
  - 윗줄이 `{` `(` `[` 또는 `BEGIN`·`THEN`(대소문자 무시)으로 끝나면 한 단계를 더 들여쓴다.
  - 키 이벤트가 아니라 `beforeinput`(`insertLineBreak`/`insertParagraph`)으로 처리한다. 안드로이드 IME에서 Enter가 `keyCode 229`로 오기 때문이다.
  - 한글 조합 중(`isComposing`)에는 개입하지 않는다.
  - Ctrl/⌘+Enter는 지금처럼 저장 단축키로 둔다.
- 들여쓰기 단위는 공백 2칸이다. *(내 판단)*
- PC 단축키
  - Tab / Shift+Tab: 커서가 있는 줄 또는 선택한 여러 줄을 들여쓰거나 내어쓴다.
  - Esc를 한 번 누르면 그다음 Tab 한 번은 기본 동작(포커스 이동)을 하게 해서 키보드로 빠져나갈 수 있게 한다.
- 도구줄은 내용 칸 바로 위에 둔다: `코드블록` · `→ 들여쓰기` · `← 내어쓰기`. 폰과 PC 모두 보인다.
  - `코드블록`을 누르면 ` ``` ` 펜스를 넣고 커서를 그 안에 둔다.
  - 선택한 글이 있으면 그 글을 감싼다.
  - 버튼을 눌러도 내용 칸의 포커스와 키보드가 유지되어야 한다(`onMouseDown` preventDefault).
- 편집할 때는 `undo`가 깨지지 않도록 `document.execCommand('insertText')`로 넣고, 지원되지 않을 때만 직접 값을 바꾼다. *(내 판단)*
- 펜스를 삽입할 때 언어 이름은 비워 둔다(사용자가 ` ```sql `처럼 직접 적는다). *(내 판단)*

**보기 (`KnowledgeNoteCard` 펼친 본문)**
- 내용을 ` ```lang … ``` ` 펜스 기준으로 나눈다.
  - 펜스 밖의 글은 지금처럼 `whitespace-pre-wrap`으로 보여 준다.
  - 펜스 안의 코드는 고정폭 글꼴과 회색 배경 블록으로 보여 주고, 가로 스크롤을 허용한다(줄바꿈하지 않는다).
- 색 강조는 highlight.js core에 sql, java, javascript/typescript, json, bash 언어만 등록해서 쓴다. 언어가 없거나 모르는 언어면 색 없이 고정폭으로만 보인다. 테마는 다크 모드에도 맞춘다. *(내 판단)*
- 각 코드블록에 "복사" 버튼을 둔다. *(내 판단 — 폰에서 코드 일부만 정확히 선택하기 어렵다)*
- 마크다운 전체를 렌더링하지는 않는다. 펜스만 해석하고, `dangerouslySetInnerHTML`은 highlight.js 출력(이스케이프됨)에만 쓴다.

**미리보기 문구 (`noteHeadline`, `StockNotesPanel`)**
- ` ``` `로 시작하는 펜스 줄은 건너뛰고 다음 줄을 첫 줄로 쓴다. *(내 판단)*

**글자 수 제한**
- BE의 내용 제한 2000자를 **10000자**로 올린다. DB 컬럼은 이미 `text`라 마이그레이션은 필요 없다. *(내 판단 — 사용자 확인 필요)*
- FE에도 같은 제한을 두고, 넘으면 저장 전에 남은/초과 글자 수를 보여 준다. 지금은 서버 400 응답으로만 알 수 있다.

## 빌더에게 맡기는 것
- 정규식 등 펜스 파싱의 세부 구현, 도구줄 아이콘·배치, highlight.js 테마 색
- 테스트: 들여쓰기 계산, 펜스 파싱, headline 처리는 단위 테스트로 검증한다. Textarea 동작은 RTL로 검증한다.
